# Демо-обработка VAEditor

`example/VAEditorSample` — внешняя обработка, которая встраивает редактор и показывает
его возможности. Она собирается в `VAEditorSample.epf` (`npm run compile`) и ездит
вместе с редактором, поэтому по ней пользователь судит о функциях.

## Где что лежит

| Файл | Назначение |
|---|---|
| `Forms/MainForm/Ext/Form.xml` | форма: элементы, команды, кнопки, списки выбора |
| `Forms/MainForm/Ext/Form/Module.bsl` | весь код демо: загрузка редактора, обработка событий, команды |
| `Forms/Autotest/…` | прогон автотестов в отдельной форме; режим зависит от `ПараметрЗапуска` |
| `Templates/VAEditor`, `Templates/StepList`, `Templates/Keywords` | макеты, из которых редактор распаковывается на клиенте |
| `StepList/ru.json`, `StepList/en.json`, `Keywords/keywords.json` | данные для провайдера Gherkin |

## Правила этой обработки

1. **Язык — русский.** Имена процедур, переменных, команд и подписи элементов — по-русски.
   Английские имена остались от ранней версии, новые не добавляем.
2. **Каждая команда показывает ровно одну возможность** и даёт видимый результат:
   сообщение, новую вкладку или изменённый текст. Команда, которая «ничего не делает
   на глаз», в демо бесполезна.
3. **Никакой логики ради логики.** Демо не проверяет ввод и не обрабатывает ошибки —
   это витрина API.

## Как добавить демонстрацию новой возможности

1. В модуле (`Module.bsl`) добавить процедуру-команду в регион
   `#Region ДемонстрацияВозможностей`:

   ```bsl
   &НаКлиенте
   Процедура ФорматироватьДокумент(Команда)
       VanessaEditor().formatDocument();
   КонецПроцедуры
   ```

   Для подсказок есть `ПоказатьПодсказку(Текст)`, для многострочного текста вкладок —
   `СобратьТекст(Строки)`.

2. В `Form.xml` в блоке `<Commands>` добавить команду. **`<Action>` обязан совпадать
   с именем процедуры**, иначе платформа не соберёт форму:

   ```xml
   <Command name="ФорматироватьДокумент" id="43">
       <Title><v8:item><v8:lang>ru</v8:lang><v8:content>Форматировать документ</v8:content></v8:item></Title>
       <ToolTip><v8:item><v8:lang>ru</v8:lang><v8:content>Выровнять таблицы и отступы фичи (Shift+Alt+F)</v8:content></v8:item></ToolTip>
       <Action>ФорматироватьДокумент</Action>
       <Representation>TextPicture</Representation>
   </Command>
   ```

3. Кнопку добавить в группу `ГруппаДемонстрация` в `AutoCommandBar`:

   ```xml
   <Button name="КнопкаФорматироватьДокумент" id="602">
       <Type>CommandBarButton</Type>
       <CommandName>Form.Command.ФорматироватьДокумент</CommandName>
       <ExtendedTooltip name="КнопкаФорматироватьДокументExtendedTooltip" id="603"/>
   </Button>
   ```

4. Проверить связку (без платформы, обычным grep):

   ```
   JGit grep "ФорматироватьДокумент" -- example/VAEditorSample/Forms/MainForm/Ext/Form.xml \
                                          example/VAEditorSample/Forms/MainForm/Ext/Form/Module.bsl
   ```

   В XML имя команды встречается минимум трижды (`<Command name>`, `<CommandName>`,
   `<Action>`), в модуле — один раз (`Процедура`).

## Грабли

- **`id` уникальны в пределах формы.** Занятые: 1–413 (элементы и команды),
  43–47 (команды демонстрации), 600–611 (группа и кнопки). Свободные — 620+.
- **`<Action>` ≠ имя процедуры** — самая частая причина «форма не открывается».
  Имя команды и имя процедуры могут отличаться, но Action ссылается на процедуру.
- **Имена элементов формы — это идентификаторы.** Если в модуле есть
  `Items.EventLog` или `Элементы.VanessaEditor`, переименование элемента в форме
  ломает код; подписи (`<Title>`, `<ToolTip>`) переименовывать безопасно.
- **Файлы в CRLF и с табами.** Правки делать табами, иначе диффы шумят.
- **Многострочные литералы BSL:** строка продолжается символом `|`, поэтому текст
  фичи с таблицами собирается массивом строк (`СобратьТекст`), а не литералом —
  иначе `|` таблицы станет продолжением строки.
- **Форма `Autotest` живёт в двух режимах.** Автозапуск (CI) — обработка открыта
  с параметром запуска `/C`, тогда пишутся метки `client-started.txt`,
  `page-loaded.txt`, `autotest-result.txt`, `success.txt` и клиент закрывается
  через `Exit(False)`. Интерактивно (`ПараметрЗапуска` пуст, кнопка «Автотест»)
  файлы не пишутся, а результат показывается сообщением и форма остаётся открытой.
  Режим различает `ЭтоАвтозапуск()` — не заменять её на проверку префикса
  `"autotest"`, префикса в параметре нет (там путь к файлу).
- **Форма компилируется только платформой.** Локально проверить можно лишь
  согласованность имён; сборка — `npm run compile` (нужен OneScript).

## Что демо обязано показывать

Держать покрытым (команда → что видно):

| Возможность | Команда демо |
|---|---|
| Загрузка/сохранение текста | `LoadFile`, `GetValue` |
| Тема (`vs`, `vs-dark`, `hc-black`, `1c`) | `EditorTheme` |
| Форматирование фичи | `ФорматироватьДокумент` |
| Символ комментария `#` / `//` | `ПереключитьСимволКомментария` |
| Навигация по шагу (события `SHOW_STEP_IN_TREE`, `OPEN_STEP_AS_FEATURE`) | `ПоказатьШагВДереве`, `ОткрытьШагКакФичу` |
| Подсветка Gherkin / BSL / xBSL и diff | `ПоказатьЯзыки` |
| Подсценарии и прогресс выполнения | `ShowSubcode`, `RunSubcode`, `NextRuntimeStep` |
| Точки останова, проблемы | таблицы `Breakpoints`, `Problems` |
| Сворачивание, шрифт, пробелы, таб | `EditorAction`, `Whitespaces`, `TabSize`, `InsertSpaces` |
| События в 1С | `EventLog` + `VanessaEditorOnReceiveEventHandler` |
| Многооконность, diff, markdown | `EditorType` |

Если появляется новый публичный метод редактора (`src/types/public-api.d.ts`) —
в демо должна появиться строка в этой таблице и кнопка, иначе возможность никто не увидит.
