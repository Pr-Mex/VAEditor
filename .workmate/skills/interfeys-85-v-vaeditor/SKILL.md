# Интерфейс 8.5 в VAEditor

## Откуда берётся оформление

В новом варианте интерфейса платформа сама публикует оформление в документ: палитру
цветов (CSS-переменные) и класс темы в служебном блоке стилей, а также объявления
основного шрифта. Тему платформа переключает сменой значений переменных — отдельных
правил под тёмную тему писать не нужно.

## Определение режима (без участия 1С)

`src/ui-interface.ts`:

- `interface`: есть переменные палитры 8.5 на `:root`/`body` → `85`, иначе `taxi`;
- `theme`: класс темы на `html`/`body`; если ни одного — `prefers-color-scheme`,
  затем `light`;
- результат ставится атрибутами `data-interface` и `data-theme` на `body`;
- URL-параметры `interface=` / `theme=` — только ручное переопределение, по умолчанию
  ничего не передаётся.

**Не пытаться определить интерфейс в коде 1С.** Клиентский способ узнать вариант
интерфейса недоступен на сервере: вызов падает в `Попытка/Исключение` и всегда даёт
`taxi`. Именно из-за этого в URL уходил `?interface=taxi` и оформление 8.5 не включалось.

## Правила CSS

- Базовые (таксишные) правила — **литералами**: старый движок не гарантирует `var()`,
  палитры там нет.
- Всё для 8.5 — под `body[data-interface="85"]`, через переменные палитры. Тёмная тема
  получается сама, отдельные правила под неё не нужны.
- Шрифт 8.5: `font-family: Roboto, "Segoe UI", Arial, sans-serif`. `Segoe UI` как
  основной — ошибка, платформа рисует Roboto.
- Шрифт, на который ссылается документ, по `file://` не подгружается: гарантированный
  Roboto — вложить woff2 в бандл (~150 КБ) либо поставить шрифт в ОС.

## Грабли

- Не тащить палитру платформы в свои `--va-*` переменные «на будущее»: цвета 8.5 должны
  приходить из платформы, иначе тёмная тема разъезжается.
- `src/types/*.d.ts` не всегда попадает в сборку ts-loader. Глобальные объявления
  (`window.VAEditorVersion`, `__VA_EDITOR_VERSION__`) держать в импортируемом
  `src/version.ts`, а не в ambient-файле.
