# Сборка и отладка страницы в поле HTML 1С

## Ограничения движка

Встроенный движок 1С не понимает синтаксис новее ES2015. Сборка обязана это проверять:
`webpack.config.js` после билда валидирует бандл (`tools/plugins/checkRuntimeCompat.js`)
и падает с сообщением о несовместимости, указывая место.

Типовые причины провала:

- приватные поля классов `#field` (ES2022) — чаще всего из сторонних библиотек;
- `**` (ES2016), `async`/`await`, optional chaining, `??`;
- стрелки и `let`/`const` допустимы, они ES2015.

Лечится `target`/`babel` до `es2015` и, если библиотека приходит минифицированной,
её заменой или исключением.

## Cannot redefine property / `defineProperties@[native code]`

Симптом: страница падает на `Object.defineProperties`, стек начинается с `global code`.

Причина: бандл встроен в страницу **дважды**. У `HtmlWebpackPlugin` с несколькими
entry points обязателен фильтр:

```js
new HtmlWebpackPlugin({ filename: 'test.html', chunks: ['test'], /* … */ })
```

Без `chunks` в `test.html` попадают и `app`, и `test`, `src/main.ts` выполняется
второй раз и переопределяет уже объявленные глобальные свойства.

Дополнительно: в дескрипторах глобальных свойств держать `configurable: true`, чтобы
повторная инициализация не бросала исключение.

## Пустая страница в поле HTML

Консоль встроенного движка конечному пользователю недоступна, поэтому любая ошибка
инициализации выглядит как белый экран. Обязательно:

- точка входа тестов (`test/autotest.js`) должна импортировать `src/main` — иначе нет
  ни разметки, ни `window.createVanessaTabs`, ни провайдера Gherkin;
- на странице — перехват `window.addEventListener('error')` и `'unhandledrejection'`
  с выводом в видимый баннер (`position: fixed`, максимальный `z-index`), чтобы ошибка
  читалась даже при не применившемся CSS.

## Воркер — отдельный бандл, полифилы страницы в него не попадают

Симптом: страница работает, тесты идут, но один падает с `ReferenceError: Can't find
variable: globalThis`, а стек указывает на `blob:file:///...` — то есть внутрь воркера.

Причина: воркеры собираются отдельными входами webpack, полифилы страницы
(`src/polyfills.ts`) к ним не применяются. Всё, чего нет в движке 1С, надо добавлять
в сам воркер: `tools/plugins/inlineWorkerSource.js` приписывает к тексту каждого
воркера `var globalThis = self;` перед упаковкой в base64.

Правило: **новый полифил для страницы — проверить, нужен ли он воркерам**. Проверка
только в браузере ничего не покажет: Chrome `globalThis` знает, движок 8.3.27 — нет.

## Что умеет движок: проверять, а не угадывать

Гадать по версии WebKit не нужно — есть режим `probeenv` в `tools/local-check.ps1`
и `check.cmd`:

```
check.cmd probeenv "C:\Program Files (x86)\1cv8t\8.3.27.2342\bin"
```

Страница `probe-env.html` (её генерирует `PrepareProbeEnv` в форме `Autotest`)
печатает в `env-probe.txt`: `userAgent`, наличие `TextDecoder`, `Uint8Array`,
`escape`, `atob`, `Blob`, `Worker`, `URL.createObjectURL` и сверяет декодирование
кириллицы двумя способами (`escape/decodeURIComponent` и `TextDecoder`).

Проверено на 8.3.27.2342 (WOW64) и 8.5.4.1878: `TextDecoder` есть в обеих,
результаты декодирования совпадают. Поэтому в `src/worker-source.ts` base64 → UTF-8
разбирается через `TextDecoder`, а `escape()` оставлен запасным путём.

Важно: проба идёт через форму `Autotest`, а не `MainForm` — см. `Initialize`,
иначе `MainForm` падает на макетах `Keywords`/`StepList`, которых нет в репозитории.

## Проверка

`dist/index.html` самодостаточен (скрипты и стили инлайном) — требование `file://`,
где каждый URL считается отдельным origin. Прогон — `tools/local-check.ps1`
(см. навык «Прогон автотестов 1С без диалогов защиты»), успех — `success.txt`.

Платформа может держать распакованные макеты и показывать старую сборку: проверять
`dist/` и версию, а не только исходники.
